# Fixed two-CPU retirement, native revoke, per-CPU ACK and physical page reuse

**Experimental candidate; full Linux acceptance remains HOLD.** Extends exact #245 without modifying any inherited implementation, test, production compiler lock or coverage row.

HIA f0 derives the ledger from the live APIC/FS/GS-bound boot arena and the PTE from live CR3 and the fixed four-level page-table layout. The five contiguous table pages must be disjoint from the slab and arena. The low identity hierarchy is read back and validated. Operation 0 requires the exact retired owner word with no ACKs and an identity leaf (allowing A/D changes), then performs a locked leaf CAS to zero and MFENCE. Operation 1 requires a zero leaf and a valid generation-bound retired owner word, executes local native INVLPG and MFENCE before atomically publishing the calling CPU's ACK bit. Duplicate, stale and mapped-page ACKs are refused. Operation 2 requires both fixed cohort bits, the original live owner, an absent leaf and available generation space. It reserves the next generation with a distinct pending ledger state, remaps the same physical page by exact native CAS, fences and invalidates locally, and only then publishes the new owned generation. A remap/publication rejection after reservation returns distinct partial status 10; callers must fail stop, not blindly retry. This is not a multiword atomic transaction.

The independent multiboot observer initializes the arena before AP startup; both CPUs really read the old identity mapping before retirement. The native owner race and separately forced BSP/AP winners are retained. The losing CPU attempts foreign revocation while mapped and foreign reuse after both ACKs. Both CPUs execute actual read #PFs after their native invalidation; CR2, fault RIP, error code and distinct CPU fault counts are checked before reuse. An owner request before peer ACK is refused with the leaf and ledger unchanged. After both ACKs the same physical backing is mapped at the original address, the owner observes its old content and writes a distinct marker at both ends, and the cooperative peer observes the new content. Old-generation ACK/retire and duplicate ACKs are rejected. Five independent source mutants (early reuse guard, revoke CAS, ACK CAS, remap CAS, final publish CAS) are detected by hardware state in both PC and Q35. Existing 528 scenarios are retained; this adds 16 focus scenarios. No old failure is reclassified.
