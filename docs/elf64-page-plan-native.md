# Native HIA ELF64 selected PT_LOAD page-plan derivation (2026-11-20)

src/elf64_page_plan.hepta is real HIA Core v8 selfhost_elf source. It closes a narrow but concrete provenance gap between an immutable ELF64 program header and the 40-byte per-page materialization prefix consumed by src/elf64_page_fill.hepta. The only caller-supplied selector is two little-endian u64 values (program-header index, segment-relative page index). The exact 40-byte mutable output consists of p_offset, p_filesz, p_memsz, p_vaddr mod 4096, and page index, all derived from the current ELF file bytes instead of being trusted as caller-provided size/address fields.

Before any write it checks image/request/output bounds, ELF64 x86-64 identity, header/program-table shape, the indexed PT_LOAD, reserved flag bits, W^X, 4 KiB offset congruence, power-of-two p_align congruence, 48-bit low-half address range, file data bounds, file size <= memory size, the existing filler cap p_memsz <= 2^32, and the selected page's memory footprint. Failures leave the whole output unchanged. Status: 0 success, 1 short image, 2 wrong selector/output size, 3 bad ELF identity or architecture, 4 malformed PH table, 5 invalid selected index or non-PT_LOAD, 6 invalid PT_LOAD geometry/permission/file bytes, 7 page outside selected segment. The output has no implicit relocation, authority token, physical frame, or address-space ID.

Independent Python byte-level oracle tests accepted and hostile cases with read-only input/red-zone checks, rejection immutability, native object/shared-library .text byte identity and two empty-PATH object rebuilds. For fully admitted static layouts, the harness also passes the HIA-emitted plan plus original immutable ELF image to the *other* unchanged real HIA page-fill object and compares every resulting page byte against an independent Python file/BSS oracle. A separately compiled dishonest HIA always-success no-op is required to diverge.

This is not an end-to-end ELF loader or authenticated multi-step transaction. The test harness constructs the envelope for the second HIA component; a malicious or racing coordinator can still replace the source between admission, planning and fill. No exclusive ownership, stable image digest, HIA physical mapping, user PTE permission publication, ET_DYN relocation, dynamic linker, stack, execve, QEMU CPL3 execution, privilege backend or SMP atomicity is demonstrated. The locked toolchain and Linux scope remain unchanged; all 17 acceptance gates and 422 syscall rows remain HOLD.
