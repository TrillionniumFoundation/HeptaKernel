# Fixed native partial transfer poison before writer reentry

Experimental HOLD, based on #252 exact 8fb1398a258447a626afce8be8c79523c2a70a80. The former cooperative wrapper released its generation-bound writer lease even when the native lifecycle returned partial status 10 after reservation. The new HIA wrapper attempts exact CAS of the held word to the same generation with reserved tag 3, instead of publishing a free next-generation word. It reports partial 10 even if this CAS loses; no automatic recovery or retry is claimed. The ordinary gate rejects a non-free word, and manual claim/release cannot match tag 3. Existing successful and safely rejected operations retain the original release and status semantics.

The independent PC/Q35 observer forces each CPU direction to be the retiring owner, executes the real reserve then remap-CAS identity mutant, observes partial status 10 and the reserved ledger without a PTE, checks the poisoned lease, attempts ordinary retry and manual claim/release, verifies refusal and unchanged state. A separate combined branch-bypass mutant instead publishes the free next generation and really acquires a new manual lease after the failed transfer. All 60 previous focused controls and 8 new controls passed (68/68) using the exact compiler. Guard, original page owner, callback and entry object checks are retained. Original inherited tests are separately rerun by the new workflow (772 + 68 = 840 planned). No independent CI PASS is claimed.

This is a fixed cooperative-path quarantine, not a general fail-stop or recovery proof, does not prevent independent page_owner/direct stores, NMI, malicious concurrent metadata remapping, or arbitrary page-table writers, and cannot guarantee poison after an unexpected lease CAS loss. No production lock, original budget, syscall obligation or Linux acceptance gate is changed.
