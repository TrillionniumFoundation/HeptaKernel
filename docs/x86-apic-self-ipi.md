# Native HIA xAPIC self-IPI and EOI experiment

The subject is actual HIA compiled by the independently rebuilt experimental #952 compiler at `fed7aac38b86c2dfb4ed03aa9491fa93b7565dad`. No production toolchain or full Linux coverage gate changes. f0 accepts only the fixed, independently UC-mapped xAPIC aperture 0xfee00000 and reserved vector 0x51, compares the live full APIC-base MSR against the expected value, rejects disabled/x2APIC mode, checks software enable and priority, requires the target IRR/ISR clear, bounds pre/post ICR polling and writes the fixed self-destination ICR. With IF cleared, it requires the real target IRR bit to become pending before returning success. f1 verifies that the target is the highest active ISR vector before a native MMIO EOI, and reads the ISR bit back.

The independent guest-only assembly observer maps the aperture, sets an IDT gate, masks legacy PIC, independently reads IRR/ISR, enables interrupts, observes one hardware interrupt, calls f1 from its handler, checks ISR clearing and returns via its own IRETQ. It restores SVR/TPR/PIC masks and checks unchanged APIC-base MSR. NOP controls remove only native MMIO stores using an independent GNU assembler encoding. Refusals include wrong base/vector, stale MSR, disabled APIC, blocked priority, already pending interrupt, and EOI without active vector.

Caller must provide the trusted UC identity mapping, IF=0 and exclusive single-CPU ownership. No address-space authority, x2APIC, cross-CPU IPI, IPI memory-ordering, native exception entry/return, or complete SMP claim. QEMU PC and Q35 cases and artifact byte identity are required before any scoped PASS.
