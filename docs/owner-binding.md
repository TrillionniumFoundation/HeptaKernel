# Native HIA physical arena / PMM state binding

`src/owner_binding.hepta` is a genuine HIA Core v8 `selfhost_elf` component built by the exact pinned upstream native self-hosting compiler and exported as a separate `f0`. The test-only linker renames that symbol to `owner_f0` without rewriting its machine instructions.

The caller supplies a **24-byte little-endian descriptor** `(physical_base, page_count, reserved_prefix_pages)`, a minimum **16-byte reply**, and an initialized mutable PMM state view. The function returns one `u32` matching the first reply word; its second reply word is the current free-frame count if status is zero, otherwise zero. A reply shorter than 16 bytes returns 1 with no output writes. A non-24-byte descriptor returns BAD_REQUEST=2. Invalid geometry returns INVALID=6; an absent, inconsistent or mismatched state header returns BAD_STATE=4.

The binding check requires a page-aligned base below 2^52, nonzero page count no larger than 65,536, reserved prefix not exceeding the number of pages, and a physical extent fully below 2^52. The state must hold at least 64+ceil(page_count/8) bytes. Its PMM magic, base, page count, and reserved prefix must equal the descriptor exactly; its free count must not exceed page_count-reserved_prefix. All 24 header padding bytes at offsets 40..63 must be zero. The native HIA checker then walks every page bitmap bit, rejects a cleared reserved-prefix bit, verifies the exact number of currently free dynamic pages against the stored free count, and requires zero unused tail bits in the final bitmap byte. Successful matching leaves the entire PMM state unchanged. This adds O(page_count) work.

An independent test initializes real PMM states via `src/kernel.hepta` before passing them to this separate native HIA module. It checks valid and invalid descriptors, first/last physical geometry, explicit zone identity mismatch, corrupted headers and padding bytes, all major bitmap boundaries, reserved bits, tail bits, live exact-claim updates, counter inconsistencies, short capabilities and state byte preservation. A deliberately dishonest separately compiled native HIA E820 object is used as a negative comparison, not as production code. `make test-owner-binding` runs this suite; `make test` requires it.

The QEMU PC/Q35 test-only handoff invokes this new HIA component on both initialized E820-admitted PMM states before allocating/reading their physical pages. The existing `arch/x86_64/boot.S` remains a non-HIA **test bridge** and the still-verified HIA E820/arena/PMM components are linked separately. Build evidence recompiles the HIA source under empty PATH and compares source object, shared-library text, renamed object text and all boot images, including negative images.

## Deliberate and critical boundaries

**Consistent metadata is not authenticated ownership.** The checker now recomputes bitmap/free-count consistency, reserved-prefix and tail-bit invariants, but it cannot authenticate foreign buffer pointers, attest E820 provenance, reject a coherently rewritten bitmap/count, or prevent multiple views of the same physical memory. After binding, the existing PMM `state_valid()` remains mandatory for every mutable PMM operation; a separate native HIA consistency check is not a license to remove per-operation checks. It does not atomically lock an arena, implement cross-zone transaction semantics or establish SMP safety. Firmware, virtual memory, interrupt entry, atomics, drivers, syscalls, and Linux compatibility are still open.

All 17 full-Linux acceptance gates and 422 x86-64 syscall obligations remain unchanged in `compatibility/coverage.json`. `make full-acceptance` must continue to exit 2 HOLD.

## Native HIA state capability

The PMM-state input is now typed `readbuf` in the HIA entry point and all state-only helpers. Only the separate reply retains writable capability. CI compiles a deliberately injected `buffer.store` on this read-only state and requires the native verifier to reject it, while the otherwise-identical writable-state positive control must compile. This establishes a narrower **static write authority** for the native checker, not authenticated pointer provenance or SMP safety: callers can still possess independent writable aliases.
