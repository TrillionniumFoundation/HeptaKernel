# Native HIA ELF64 4 KiB file/BSS page materialization (2026-11-20)

`src/elf64_page_fill.hepta` is genuine Core v8 `selfhost_elf` source for a **single 4 KiB destination page**. It is intentionally separate from header and `PT_LOAD` admission. The caller must have already checked the ELF program header, page ownership and destination permissions. The primitive does not grant that authority.

The 40-byte little-endian request prefix is part of the first **read-only** buffer. It contains five `u64` fields in order: ELF file offset, file bytes, memory bytes, leading byte offset in the segment's first 4 KiB page, and segment-relative page index. The remaining bytes of that input buffer are the unmodified ELF file. The second argument is an exact 16-byte mutable receipt, and the third is an exact 4096-byte destination page. On success, the native program clears the entire page, copies exactly the intersection of the selected page with the segment's file-backed bytes, leaves all BSS and out-of-segment bytes zero, and writes receipt `a5 00 ... 00`. It never modifies the source envelope. On any refusal, both output buffers must remain completely unchanged.

Validation is performed **before the first write**: minimum request size, receipt and page lengths, `p_filesz <= p_memsz`, positive `p_memsz`, lead in `[0,4096)`, `p_memsz <= 2^32`, page index at most `2^20-1`, complete file range in the supplied source and page index within the segment's memory footprint. These conservative size restrictions are part of this component's current contract, not Linux limits.

Return codes: 0 success; 1 short prefix; 2 wrong receipt length; 3 wrong page length; 4 malformed fields or limit; 5 truncated source bytes; 6 out-of-range segment page. No host libc, Linux syscall, foreign routine, embedded external machine code or interpreter implements the fill. The verified HIA-native source is compiled to a freestanding x86-64 ELF object, linked to a test-only shared library and independently byte-compared with two empty-PATH native rebuilds.

`tests/test_elf64_page_fill.py` independently projects each virtual-memory byte from source bytes, checks complete frame contents and BSS zeroing, watches all input/red-zone bytes, checks refusal immutability, uses deterministic randomized and boundary campaigns, and rejects a real compiled HIA dishonest always-success no-op. This is stronger than only checking the status code.

This does **not** allocate a physical frame, verify ELF metadata authority, construct a mapping or PTE, load a multi-segment process, establish entry-point address rights, implement `ET_DYN` relocation, TLS, a stack, `execve`, syscalls, CRx, IRETQ, atomic publication or SMP TLB shootdown. It has no new QEMU CPL3 execution evidence. The full Linux 7.3.4 / all-architecture acceptance and all 422 x86-64 syscall obligations remain HOLD. The non-HIA `boot.S` bridge remains explicitly non-HIA.
