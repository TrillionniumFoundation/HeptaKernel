Experimental HOLD candidate based on #247 exact 09f2e84d0aff8dd72d34e974a1d36ea1f9b6a830. The native HIA page lifecycle now checks the other 511 leaves of the validated fixed low identity page table for any present mapping to the target physical frame (physical-address mask, independent of A/D and permission flags). The target leaf is excluded because it legitimately changes between present and absent. A conflicting leaf causes status 6 before ledger or target PTE mutation. The check is shared by revoke, ACK and reuse admission; it is a snapshot, not a page-table writer lock.

Independent PC and Q35 two-vCPU observer installs a real alternate leaf at VA 0x80000, reads both ends of the physical page before attempting the original owner revoke, and checks status 6, unchanged retiring ledger, unchanged original leaf and continued alternate mapping read. A separate native source mutant bypasses the admission branch, actually clears the original leaf, and proves the alternate mapping still reads the same old page. Both controls exit independently. The full previous transfer focus is rerun under the new source, including normal cross-owner transfer in both directions, missing ACK and scrub mutants. Local exact compiler run: 20/20. Independent CI must additionally rerun all 560 inherited scenarios; no inherited evidence is replaced.

This candidate does not establish alias exclusion via upper-level/huge-page mappings, arbitrary page tables, concurrent page-table mutation, noncooperative CPU access or general physical memory isolation. The alternate alias is deliberately preserved in the rejection test; the test is not an alias teardown mechanism.
